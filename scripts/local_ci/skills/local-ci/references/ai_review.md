# AI 补充审查与测试

按 PR 意图和实际改动选择接口、算子语义/lowering、JIT、缓存、并发、性能、LLVM/依赖、权限与 CI 协议等专项方向。同一任务可触发多个方向，均由当前唯一 Codex 完成，不创建并行审查 Agent。

优先调用现有测试；生成的复现脚本只能在任务目录中使用并随结果保存。风险记录须指向具体变更和执行证据。产品代码导致的确定性高风险失败、基础设施错误、既有问题和证据不足的推测必须分开。后者仅报告，不能使 PR 被判代码失败。

对高风险问题使用相同脚本、相同环境测 candidate 两次和 base 一次，通过可信 `execution_ids` 建立可追溯归因。先分别完成复现所需的 base/candidate 构建和安装，不能混用 wheel。任何模型自述、PR 标签或生成 JSON 都不能代替执行器记录。

只有因本次变更新增的 HIGH/CRITICAL 问题，且满足上述两次 candidate 失败、base 通过的证据条件，才可作为此类代码问题的阻塞依据。证据不足时继续收集或列为非阻断风险；必要验证仍无法完成时如实报告未完成，由 Harness 按兼容协议封存，不伪造结论。
